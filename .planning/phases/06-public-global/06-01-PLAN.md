Final.
1. Migration 0008 (Phase 1's clean-up is 0003, Phase 2's 0004, Phase 2.1's 0005, Phase 3's 0006, Phase 5's 0007; if Phase 4 added one, Phase 5's is 0008 and this is 0009; hand numbered; never `migrate create -seq`; re-check with `ls migrations` and rename the files, the test name and the numbers in 06-03 if the built numbers differ) adds `post_reports`, `comment_reports` and one index. Nothing in `users` (Phase 2.1 owns the column), nothing else in `entries` or in Phase 5's comments table.
2. **The setting is read, never written.** Every Global page, person read and single-post fact joins `users` and reads `account_visibility` at that moment. There is no copy per post and no cache, so a person who switches to private leaves Global at once (past posts included) and one who switches to public appears at once (Phase 2.1 D-12). Fixtures set a person's value through `PATCH /v1/me` with the field `account_visibility`; no Phase 6 file writes the column.
3. **The author is public** when `users.account_visibility = 'public'`. There is no age rule, no under-18 refusal and no second table in this phase. A person under 18 starts private and may switch (Phase 2.1 D-11); that is a recommendation the developer can drop, noted in the threat model and the launch list, not a rule here.
4. The visibility rule (the one function): `CanView = IsOwner || (!Blocked && ((AreFriends && ViewerPostedThatDate) || OwnerPublic))`. Reading a post's comments and writing one need exactly `CanView` (`CanComment = CanView`, as plan 05-01 already has it): whoever can see a post can read and write its comments, so a stranger may comment on a public post and a blocked pair can do neither. `CanReact = CanView && !IsOwner`. A comment's `can_delete` is the writer or the post's owner (Phase 5's rule, unchanged). `ViewerPostedThatDate` is a `posted_days` row for the entry's `local_date` (any source), as in Phase 5.
5. Not visible answers 404 `not_found` with the same body as a missing id, on every route. Ids are UUIDs parsed in Go; a non-UUID is 404.
6. Global: `GET /v1/board?view=global`. Entries of authors whose column says public, newest first by `entries.created_at` then `id`, keyset paging on `(created_at, id)`, 20 by default, 1 to 40. Excludes the viewer's blocks in both directions and every entry the viewer reported. Includes the viewer's own public posts (`mine` true). Not gated.
7. Person: `GET /v1/people/{user_id}`. 404 for the caller's own id, an unknown id, a blocked pair (either way), and anyone whose column is not public, who is not a friend and has no request with the caller. Otherwise the person, the `relation`, the `visibility` (the column, as sent), and `posts`: the same cards as Global for that author when the column says public, else null.
8. Post report: `POST /v1/posts/{entry_id}/report` with `reason` one of `spam`, `unkind`, `not_public`, `other`. The reporter must be able to view the post (else 404) and must not own it (409 `own_post`, Phase 5's code). One report per person per post: a repeat is a 200 and stores nothing new. The post disappears from that reporter's Friends board, Global and person lists at once (every list query excludes it for that reporter). A direct fetch of the post by its id still works (the owner and others are unaffected). Nothing is hidden, removed or counted automatically.
9. Comment report: `POST /v1/comments/{id}/report` with `reason` one of `spam`, `unkind`, `other` (`not_public` is `invalid` here). The reporter must be able to view the comment's post (else 404) and must not be the comment's writer (409 `own_comment`, a new code). One report per person per comment: a repeat is a 200 and stores nothing new. The comment is left out of that reporter's comment lists and counts at once; everyone else, the writer and the owner included, still sees it. The post's owner may report too (the app shows them 'Delete' instead, so only a hand-made request reaches it). Nothing is hidden, removed or counted automatically.
10. Blocked writers: a comment written by anyone blocked with the viewer (either way) is left out of the viewer's comment lists and counts, and a blocked pair cannot read or write comments on each other's posts (the post itself is 404 for them).
11. Photo links: Phase 5's single link function is extended, not duplicated: it builds a link only for an entry the visibility function allows for that viewer. Real friend-only or signed links still wait for the real storage account (launch list).
12. Cursors are opaque (URL-safe base64 of the created time and the id), validated on decode (a bad one is 400 `cursor` invalid). They carry a position only, never permission.
13. Time: no `time.Now()` in new code. `now` comes from the per-account clock accessor the spin service uses, once per call.
14. The test reset also clears the caller's `post_reports` and `comment_reports` (as reporter). Reports on the caller's own posts and comments go with the entries and comments (cascade). The reset does not touch `account_visibility`.
15. No change to `internal/user`, `ApiUser`, `/me`, sign-up, the avatar flow, `s3.go`, `errors.go` or `spin_errors.go`.
16. **Delete and block is not a server feature.** The app (plan 06-02) deletes a comment that is not the caller's with Phase 5's `POST /v1/comments/{id}/delete` and then blocks its writer with Phase 5's `POST /v1/blocks`, two existing calls in that order. Nothing new is added to the server for it and there is no transaction across the two calls. If the block call fails after the delete succeeded, the comment stays deleted (a delete has no undo), the writer is not blocked and nothing on the server tries to repair that: the app says so and offers the block again, and a repeat block is harmless (a block of an already blocked pair is a 200 in plan 05-01; record the built answer in the summary). If the delete fails, the app sends no block.
</binding_decisions>

| Report flood or one person reporting everything | Mitigate | One report per person per post or comment (unique), 10 a minute, and the only effect is hiding the post or comment for that reporter. Nothing is removed for others. |
