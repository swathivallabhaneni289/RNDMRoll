4. Local only. The daily trigger is a calendar trigger at hour 20, minute 0 (read the installed `node_modules/expo-notifications/build/Notifications.types.d.ts` and use the daily trigger shape it names: the `DAILY` trigger type with `hour` and `minute` in current versions, `{ hour, minute, repeats: true }` in older ones; write the shape in the summary). 5. `REMINDER_HOUR` 20 and `REMINDER_MINUTE` 0 live in `lib/reminder/plan.ts` only. The phone's own calendar handles the zone and daylight saving.
6. `sync(userId)` cancels every scheduled notification and then, only when the switch is on and the permission is granted, schedules exactly one. It runs when Today opens for a signed-in person and when the app returns to the foreground. The foreground handler shows nothing while the app is open.
7. The phone keeps two values per account in `expo-secure-store`: `rndmroll.reminder.<userId>.on` and `rndmroll.reminder.<userId>.asked`, each `1` or absent. Not in `lib/session/store.ts`, which is not edited.
8. The sheet is asked when Today's state is `posted`, the person was never asked, the module is available and the system permission is undetermined, 600ms after the state appears. 'Not now' marks it asked and it never shows again. A permission already granted or denied never shows it.
9. **Every sign-out cancels the schedule, with no edit to `lib/session/store.ts`, `components/profile/ProfileForm.tsx` or a launch file.** `useReminder` is mounted by `TodayScreen`, so it lives for the whole signed-in session, and it reads the session `status` from `useSession()`. It cancels every scheduled notification (`cancelForSignOut()`, which never throws) in two places: (a) an effect that runs whenever `sessionAction(status)` is `'cancel'`, that is whenever the session status is `'unauthenticated'`; and (b) the cleanup of its mount effect, which runs when the signed-in screens unmount (the root guard removes the `(app)` group as soon as the status leaves `'authenticated'`). Every sign-out path that happens while the app is open ends in `doSignOut` setting that status: the Log out row on Settings and the Log out button on Edit profile both call the session's `signOut()`, and an expired session (a definitive refresh failure) calls `doSignOut` too. So one hook covers all three, and the next person's schedule is built when Today opens for them. **(c) A session that ended while the app was closed** (a refresh token revoked by a password change on another phone, or run out during a long absence) cannot be seen by that hook, because a signed-out launch never mounts `(app)` or Today, and a repeating local notification stays scheduled in iOS across launches. Every signed-out launch starts on Welcome (`app/index.tsx` redirects every state that is not signed in and finished to `/(auth)/welcome`, and `app/(auth)/_layout.tsx` pins it as the initial route; neither is edited), so a second hook, `useReminderSignedOut()`, is called once by `app/(auth)/welcome.tsx` and calls `cancelForSignOut()` in a mount effect. Welcome is a Phase 1 screen, not a layout or a launch file, and the call changes nothing on screen. What no code can do: while the app is closed nothing can cancel, so on a phone whose session ended in that time the reminder can still show once a day until the app is next opened; its words are the same neutral ones for everyone.
10. Tapping the notification calls `router.navigate('/(app)/today')`. The listener is registered by the hook the Today screen already mounts for the whole signed-in session.
