<binding_decisions>
Final.
1. `03-UI-SPEC.md` is the design; the wire contract is `03-01-PLAN.md` Task 3b. This plan adds no string and no field.
2. The entry page is a component, `EntryView`, with a thin route `app/(app)/today/entry.tsx` that takes the entry id and a `from` value (the Back label: 'Today' when it was opened from Today, 'Diary' from the Phase 4 diary; Phase 3 only passes 'today'). The Phase 4 diary mounts the same component. Edit is its own route, `edit-entry.tsx`, also taking the id. Both treat an id that is not a UUID as 'This entry isn't here any more.' and never call the server with it.
3. Edit reuses `EntryForm` in mode 'edit' with the `CategoryHeader` edit variant. Only fields the person changed are sent. When the photos changed, the whole ordered `photos` list is sent: `{ id }` keeps a photo and `{ photo_key, photo_source }` adds a new one (each new photo is uploaded once through the plan 03-02 memory), and at least one photo must remain. Clearing the reaction or the comment sends an empty string.
4. Delete is `POST /entries/{id}/delete`. The client gets no DELETE (`lib/api/client.ts` is not edited). A 'not found' answer counts as done.
5. Skip: the link 'Skip this one' lives in `DayActions`; it opens the `ConfirmSheet` of UI spec 3.5; 'Skip it' closes the sheet and sends `skipDay(forDate, spinSeq)` from the shown spin; the answer's `today` goes into the store; a failure shows its message under the link (no Try again button). A skip is final: there is no undo.
6. `ConfirmSheet` (built in Phase 2) gets one optional per-row flag, `destructive` (default off), used only by the delete sheet.
7. The week dots follow UI spec 8 (as changed by Phase 2 revision 5): posted, then skipped (the dash), then today's ring, then the small `divider` dot (a day to come, or a past day with nothing). Every letter stays `muted`.
8. No launch file is edited. The only layout edit is adding `entry` and `edit-entry` to the Home stack.
9. The cutover is Phase 2's recipe with Phase 3's numbers. The API never migrates itself. `migrate down` is never run on dev. Throwaway accounts only; the four real accounts (`smoke-test@example.com`, `ava.stone.1004@example.com`, `test1@gmail.com`, `test4@gmail.com`) are never edited, deleted, used with the test tools or listed in `SPIN_TEST_USER_EMAILS`, and nothing is bulk-deleted.

11. The walkthrough is short: five small groups, one at a time, "group done" or what looked wrong. Claude moves time with the test tools exactly as in Phase 2 (a clock set, a clock reset, and an account reset, never mixed up).
12. The entry page has no bottom bar (UI spec, entry page, revision 6): a pinned 'Edit | Delete' footer takes its place. Phase 2's Tabs layout already hides the bar while the focused route of the `today` tab is `entry` (plan 02-02 Task 3e, `getFocusedRouteNameFromRoute`; the route is `app/(app)/today/entry.tsx`), the same way it hides it for `notifications`, and plan 03-02 added `log` and `edit-entry` to the same list, so this plan edits no launch file. Check on the device that the bar is gone on the entry page and back on Today.
