<binding_decisions>
Final.
1. Migration 0005 (Phase 1's clean-up is 0003, Phase 2's is 0004; hand numbered; never `migrate create -seq`) adds `entries` and two small things to `spins`: the column `settled_at` and `unique (id, user_id)`. Nothing else, and nothing in `users`.
2. One entry per local date: `unique (user_id, local_date)` and `unique (spin_id)`. The entry's spin is the date's latest spin at post time (a bonus counts). Category id and written name come from that spin; the entry copies neither.
3. The table holds `photo_key` (folder and file name). `photo_source` ('camera' or 'library') is stored and never shown. No response carries the key; responses carry `photo_url`, built by the server from the key and the storage public base.
4. Reaction is one of six names or null: a database check and a Go list. The same six, in the same order, as `lib/entry/reactions.ts` in plan 03-02.
5. A post runs inside one `InUserTx` (the state-row lock, then the work): re-read the zone and read `now` once; existing entry for the date with the SAME `photo_key` returns it (`already`); `daySettled` is `ErrDaySettled`; the spin number the phone saw must equal the latest spin's `seq` (`ErrSpinChanged`); the date's `late_until` passed is `ErrClosed`; then insert the entry, call the posted-day helper, set the spin's result to `posted` with `settled_at = now`. Any failure rolls all three back.
6. `MarkPosted` keeps its signature, its transaction and its Phase 2 tests. Its body moves into a helper that takes an open transaction (`markPostedIn`); both call it. The helper holds all the rules: late is `now >= closes_at`; a date past `late_until` is refused for source `post`; the week count; the bonus grant.
7. A skip sets the latest spin's result to `skipped` and `settled_at = now`. It writes no posted day, touches no goal week and grants nothing. It is refused when the day is settled, when the spin number differs, and when `late_until` has passed. A repeat skip returns the same answer (`already`).
8. Delete removes the entry row only. The `posted_days` row and the spin's result stay, so the day cannot be posted again. Edit changes title, stars, reaction, comment and photo; never the date, category, late stamp or posted day; no time limit.
9. Delete is `POST /v1/entries/{id}/delete` (the app's client has no DELETE and gets none). A repeat create with the same `photo_key` is the retry rule.
10. After a change that drops a photo (replace or delete), the handler asks the store to remove the old file after the commit, best effort: an error is logged and ignored. Nothing else ever deletes a file.
11. Today's states (Task 1c) use `spins.settled_at`: a post or skip made at or after the spin's `window_closes_at` (in the late window) keeps Today on `posted` or `skipped` for that spin until the next opening; one made earlier returns to Phase 2's `waiting` after midnight.
12. The test reset (`POST /v1/test/reset`) also deletes the caller's entries first and ALL the caller's posted days (any source), then spins and goal weeks, and sets `bonus_held` to 0. Photo files stay in storage.
13. Time: no `time.Now()` in new code. `now` comes from the per-account clock, once per call, after the lock.
</binding_decisions>

<threat_model>
| Threat | Result | Why |
|---|---|---|
| Another person's entry or photo | Mitigate | The caller comes only from the token. Every query has `user_id = caller`. Ids are UUIDs parsed in Go. A photo key is accepted only if it is exactly the caller's folder and a server-made file name. A foreign id answers 404. |
| A half-finished post (a posted day made by a post with no entry, or an entry with no posted day) | Mitigate | One transaction for the entry, the posted day and the spin result, proved by fault injection on Postgres. (A delete leaves a posted day with no entry on purpose; that is the rule, not a fault.) |
| Double post, post and skip racing, a stale screen | Mitigate | The state-row lock, `unique (user_id, local_date)`, `unique (spin_id)`, the settled check, and `spin_seq`. A retry with the same photo key returns the same entry. |
| The phone lies about the date or lateness | Mitigate | The server picks the spin, computes late and the window from its own clock. `for_date` only selects an existing spin. |
| A deleted post reopens the day | Mitigate | Delete removes only the entry. The posted day and the spin result stay, so every later post or skip is `day_settled`. |
| A post attached to a category the person never saw | Mitigate | `spin_seq` must equal the latest spin's number. |
| Odd or huge text, odd files | Mitigate | Rune limits, control characters refused, fixed error text, the 16 KB cap, the type and length bound into the signed upload, a 50 MiB ceiling. |
| Photo files left behind, links readable by anyone with the link | Accept, flagged | Unused and reset photos stay in storage. Links are public until Phase 5 swaps in friend-only links. Fine for a small test group. Flag before any outside user. Storage has never run against a real bucket, and the real key needs delete rights. |
| Photo object never uploaded | Accept | The server does not check the file exists (the avatar flow does not either). The person sees a broken photo and can replace it. |
| Test tools writing real data | Mitigate | Unchanged from Phase 2: four settings, listed throwaway emails only. The widened reset hits only the caller. |
| The four real accounts | Mitigate | `users` is unchanged; every table references it with cascade; nothing here deletes accounts. |
