1. `02-UI-SPEC.md` is the design. Every string comes from its sections 10 and 11. This plan adds none. Strings say "spin", never "roll".
2. The landing is `/(app)/today`, an explicit child path, never a bare `/(app)`. The one exception is first run (decision 11): `app/index.tsx` sends to `/(app)/profile` while `extrasPending` is true.
3. Home is a Stack inside a tab: Today, then Edit wheel or Notifications. The bottom bar stays on Edit wheel and is hidden on Notifications (the developer's Notifications picture has none). The editor guards every way out (Back, the iOS swipe, a Home or Spin tab press that pops the stack) with a `beforeRemove` listener that opens the leave sheet, and sets `gestureEnabled: false` while changes are unsaved. Save is pinned above the bar and the keyboard. The Profile tab keeps its own Stack.
4. The middle Spin button never becomes the selected tab. It goes to Today and sets `pendingSpin` in `todayStore`. Today consumes it (sets it false) only after the focus refetch has settled and the state is `open`; if not open it is cleared and nothing spins. No timer and no route parameters. The leave sheet clears it too.
5. Today asks the server again: on mount, on tab focus (so a moved test clock shows), on foreground, when a countdown reaches zero, and at the server's `next_open_at` and close time in every state that has one (nearest first, re-armed after each fetch). If the answer at zero still says waiting, ask again after 1 second, at most 5 times. While the wheel turns, triggers are ignored and one refetch runs when it lands. After `spin_closed` or `spin_not_open` Today refetches and shows the message once; "Try again" for those two is a refetch, not a new POST (only a network failure re-sends the same request). A failed refetch with data on screen keeps the screen and retries once after 5 seconds.
6. The countdown counts from the server's `now` with `performance.now()` (monotonic), marked when the request starts, never the phone's clock. On foreground the anchor is dropped and the Loading digits show until the refetch succeeds.
7. `lastReportedZone` lives in memory. The phone reports its time zone on mount, on foreground and when `deviceTimeZone()` differs from it, never on tab focus (the server limits reports to 20 a minute). A failed report does not block Today (the server uses the stored zone) and is retried on the next trigger. If the zone cannot be read, the plain "Something went wrong" message shows.

9. `app/_layout.tsx`, `app/(auth)/_layout.tsx` and `lib/session/store.ts` are not edited (the store is only read, through `useSession()`). If a cold launch shows one must change, stop and ask the developer first.

**c. Pure logic** (no React, no app imports, so each file reads on its own). Angles are degrees clockwise from 12 o'clock, and a positive rotation turns the disc clockwise.
- `geometry.ts`: `drawnAngles(weights)` (true angle `360 x weight / total`, floor 22 degrees, redistribute until none is under 22); `wedgePath(a0, a1, r)` = `M 0 0 L polar(a0) A r r 0 {large} 1 polar(a1) Z` with the large-arc flag `{large}` = 1 when `a1 - a0 > 180`, else 0 (weights 10 and 1 draw a wedge near 327 degrees); `polar` copied from `BrandMark.tsx`; `toneIndexes(n)` (UI-SPEC 2, written as the rule, for counts 2 to 12: wedge i is `dark` when i is even and `light` when i is odd, so the first wedge is dark; when n is odd the last wedge is `mid` instead, so it differs from both the wedge before it and the first wedge); `labelColorFor(tone)` (`dark` takes `dominant`, `light` and `mid` take `ink`); `poseOf(centre)` = `-centre` (the rotation that brings that centre to 12 o'clock); `targetRotation(current, pose)` = `ceil((current + 1800 - pose) / 360) x 360 + pose`, always called with the winner's pose, and the rest rotation is the pose of the shown wedge (the first wedge with no spin); `wedgeUnderPointer(rotation, angles)` = the wedge containing `(360 - rotation mod 360) mod 360`; `labelPlacement(centre, angle, name, radius, finalRotation)` (UI-SPEC 3; replaces the older `labelFlip`) returns `{ direction: 'across' | 'along', flip }`: `across` (perpendicular to the wedge's centre line, the label's centre at 70 percent of the radius) when the estimated word width `n x 8.3` dp plus 4dp is at most the room `2 x r x tan(angle / 2)` at that radius (`r` = 70 percent of the wheel radius), else `along` (on the centre line); `flip` is true when the word's baseline, after `finalRotation`, would point left of vertical, so no word reads upside down in the pose the wheel stops in (one rule for both directions; pure, no text is measured on the phone); `labelLine`, `truncate(name, n)` (the room is `2 x r x tan(angle / 2)` when `across`, the centre line when `along`), `sharePercent(weights)` (true shares, whole numbers).
- `countdown.ts`: `split(msRemaining)` into two-digit hours, minutes, seconds; `spokenMinutes(ms)` (whole hours and minutes for the spoken line "Opens at 8:00 PM, in 5 hours 4 minutes").
