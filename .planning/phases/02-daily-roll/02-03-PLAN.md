<threat_model>
| Threat | Result | Why |
|---|---|---|
| Migration damages the dev database | Mitigate | Data dump kept outside the repo, binary backup, rehearsal on a throwaway copy with a URL guard, `up 1` only, user count compared. 0004 only adds tables. |
| A real account is changed, deleted or given the test tools | Mitigate | The walkthrough uses a throwaway account. Only throwaway emails are on the allow-list. Deletes go by id inside a transaction that checks the returned email. |
| Test tools or a moved clock left on | Mitigate | The server refuses to start with them outside `APP_ENV=test`; the refusal is checked on 9091. The clock is per account. Before Group 9 the clock is reset and checked and the API restarts without the variables. |
| Rollback fails | Mitigate | `api.pre-phase2` and the dump exist first. The old binary ignores the new tables. `git revert` for code. |
| Launch breaks and static checks miss it | Mitigate | Launch checked right after the code is written and again after the cutover, by recording the first frames, in the cases of Task 2 (including a brand-new sign-up, walked by hand in Group 8b). |
| Developer reads dense output | Mitigate | The walkthrough is small groups of short steps. |
</threat_model>
