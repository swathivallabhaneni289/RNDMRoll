<binding_decisions>
Final.
1. The starting wheel is made on first use, not at sign-up or in the migration, so the dev accounts get one when they first open Today. One transaction inserts the state row and six categories; a second caller waits, then finds them.
2. Starting wheel: Meal 3, Movie 1, Song 3, Book 1, Place 2, Game 1.
3. The time zone has its own table. Nothing is added to `users`, `ApiUser` or `/me`. Routes use GET, POST and PATCH only.
4. Posted days live in `posted_days`. In Phase 2 only the test tools fill it (source `test`); Phase 3 writes `post`. A `test` row hides a real post for that date (Phase 3 must know).
5. Week is Monday to Sunday in the person's zone. `WeekStartDay` and `DefaultWeeklyGoal` (4) are named constants in `internal/spin/week.go`, the only places for those numbers (the column has no default). The server sends each day's letter and weekday name.
6. The first partial week counts like any other. The state row keeps `seeded_at`, `seeded_local_date`, `seeded_tz` (from the service clock) so Phase 3 can skip that week for a streak. No streak number in Phase 2.
7. A bonus is earned the moment the week's goal is reached. One is held at most; if one is held, the week still counts as paid and nothing is added. An unused one carries over.
8. The server computes the local date from its own clock and the stored zone, reads `now` once per request after the lock, and returns it as `Today.now`. `for_date` only selects an existing spin or a refusal; it is never stored and never decides the date.
9. Bonus spins draw from the wheel snapshot of today's spin.
10. Test tools exist only when `APP_ENV=test`, `SPIN_TEST_TOOLS=1`, a non-empty `SPIN_TEST_USER_EMAILS` and a database name ending `_dev` or `_test`; otherwise the server will not start. Only listed accounts may use them.
11. The clock goes to the spin slice only (not tokens, limiter or refresh expiry) and is per account.
12. `daySettled(date)` is the one rule for a settled day: a `posted_days` row exists, or the spin's `result` is not `open` (Phase 3 sets that, and skipped). Bonus, `can_use` and the response's `spin.result` use it (`posted` when a posted row exists, else the stored value).
13. Travel: one daily spin per local date and 12 hours at least between daily spins. Flying west can cost a day; a zone change cannot buy a second spin inside 12 hours (told to the developer on 2026-10-08 as decided unless they object; no objection).
</binding_decisions>

Go does not promise which instant `time.Date` gives when local midnight is skipped or repeated, so a date's first instant (`DayStart(D)`) is built by a rule: start from `time.Date` at midnight; while the local date is wrong, move to the end of the zone period (`t.ZoneBounds()`, or plus 1 hour); while the instant just before is still in the later date, move to the period's start. `WindowFor(D, loc)` gives `opens_at` (20:00 on D), `closes_at` (the first instant whose local date is later than D, built from midnight of D+1 by that rule) and `late_until` (`opens_at` of `LocalDate(closes_at)`). **c. Service** (`internal/spin/service.go`). Inside the lock each call re-reads the zone and reads `now` once.

- `Spin(ctx, userID, forDate)`: `forDate` optional (default the server date). In order: a daily spin already on `forDate` is returned `already=true`; `forDate` earlier than the server date is `ErrClosed`, later is `ErrNotOpen`; before 20:00 `ErrNotOpen`; a daily spin under 12 hours old `ErrNotOpen`; else `Pick`, insert seq 0 with the wheel snapshot. - `Bonus(ctx, userID, afterSeq, forDate)`, both required. - `POST /v1/spin` `{"for_date":"2026-10-07"}` (optional; an empty body counts as `{}`, accept `io.EOF`) gives 201 for a new spin, 200 for the same again, both `{"already": bool, "today": Today}`. 10 per minute.

- `GET /v1/wheel` gives `{"version":3,"categories":[{"id","name","weight","position"}],"limits":{"min":2,"max":12,"name_max":24,"weight_min":1,"weight_max":10}}` (no archived). 60 per minute.
