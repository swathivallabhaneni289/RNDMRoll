# Plan 02.2-01 summary: smooth tab transitions

## What was built

- `lib/motion/navigation.ts` (new): `pressMs` 90, `tabFadeMs` 200, `barColorMs` 220 and `easeOut`, the same curve as every other entrance (it is `EASE_OUT` in `primitives.tsx`, which is now exported; nothing else changed in that file). It also holds `useNavReduceMotion` (Reanimated's `useReducedMotion`) and `useFocusProgress(focused)`, a 0 or 1 shared value that glides between the two over `barColorMs`, starts at the current state so nothing animates at launch, and is set at once under Reduce Motion.
- `components/nav/TabIcon.tsx` (new): one bar icon, 24dp, same Ionicons names as before, colour glides between `muted` and `ink`.
- `components/nav/TabLabel.tsx` (new): one bar label, `type.label`, weight 400, colour glides between `muted` and `ink`.
- `app/(app)/_layout.tsx`: `animation: 'fade'` (or `'none'` under Reduce Motion) with a `transitionSpec` of `tabFadeMs` and `easeOut`, set once in `screenOptions`; Home, Diary, Board and Profile use `TabIcon` and `TabLabel`. `SpinTabButton`, the bar style, the hidden-bar rules, `unstable_settings` and the tint colours are untouched.
- `scripts/check-navigation-motion.ts` (new, throwaway): reads the files as text (the motion files cannot be loaded by Node) and checks the three numbers, the shared curve, that `PressScale` still holds the same 90, that no bar file holds a duration or starts a timing of its own, the layout wiring, and tokens and wording on the new files.

## How the icon colour is animated

The plan's fallback was used, not an animated colour prop. Each icon is two copies of the same glyph: the `muted` copy stays in normal flow and sizes the box (so nothing shifts), the `ink` copy lies exactly over it and its opacity goes 0 to 1 over 220ms with the shared curve. Because both copies are the same glyph, the blend is the straight mix of the two colours, so the outline never changes shape or weight. The `muted` copy is switched off once the glide has fully arrived, so at rest exactly one glyph is drawn, as before. This was chosen because it needs only opacity, which Reanimated animates everywhere, and I could not prove on a device that Ionicons passes an animated `color` through.

The label is one `Animated.Text` whose colour is `interpolateColor(progress, [0, 1], [muted, ink])`.

## Where it differs from the plan

1. **Icons need the real focus from the layout.** The installed bar draws every icon twice, one copy with `focused` fixed to true and one fixed to false, and flips which is visible at once. The `focused` the `tabBarIcon` callback gets therefore never changes, so a `TabIcon` fed from it would never animate. The layout reads the tab navigator's own state instead (`isSelectedTab` in `TabIcon.tsx`), once per screen, and passes it in. `navigation.isFocused()` was avoided on purpose: it also goes false while a page covers the whole tab group, which would replay the glide on the way back. Both copies get the same value, so they glide together and the instant visibility flip cannot be seen. The label is drawn once and its callback does get the real `focused`, so it uses that.
2. **A function `tabBarLabel` turns the bar's own text styling off.** `TabLabel` sets what the bar used to apply: `type.label` at weight 400, one line, centred, transparent background, no font scaling. `tabBarLabelStyle` in the layout stays but is not used for these four while the label is a function.
3. **The spoken label is restored.** On iOS the bar speaks "Home, tab, 1 of 5" only for a text label. With a function label it would speak just "Home". `spokenTabLabel` (in `TabLabel.tsx`) hands the same sentence over through `tabBarAccessibilityLabel`, iOS only, as before. Added line per screen in the layout.
4. **Reduce Motion is read once at app start.** Reanimated's `useReducedMotion` does not update while the app runs. After changing the setting in iOS Settings, close the app (swipe it away) and open it again, or the check will look like a failure. The hook is named `useNavReduceMotion` on purpose: a live hook called `useReduceMotion` already exists in `lib/motion/useReduceMotion.ts` (used by the wheel and the Spin button), and the two must not be mixed up. If a live reading is preferred for the bar, it is a one-line change in `navigation.ts`.
5. **`pressMs` is exported but not used by the bar.** `PressScale` keeps its own 90 (out of scope here). The four plain tabs keep the bar's own press feedback; the 0.97 compress of D-03 exists only on the Spin button. The check script fails if the two 90s ever drift apart.
6. **D-07's content rise 400 and image reveal 450 are not re-exported.** The plan's binding decision 2 lists only the three numbers and the curve; those two stay as defaults in `primitives.tsx`.
7. **The launch check, screenshots and the feel check were not done here.** They are the developer's (the phone and Metro were not touched).

## What the developer should feel and check

1. Cold launch the dev client (a launch file changed). It should land on Today with no flash of Welcome or Unmatched Route.
2. At rest the bar should look the same as before: icons, labels and heights. Compare a screenshot with an earlier one.
3. Tap Home, Diary, Board, Profile in turn and back. Each switch should be one calm fade of about a fifth of a second, and the icon and label colours should melt rather than blink. Nothing should bounce, jump or replay a list.
4. Watch for a grey or white flash in the middle of a fade. A cross-fade shows what is behind the tabs for a moment. If it flashes, the fallback is one line in the layout: `animation: 'none'`.
5. A selected icon that looks slightly heavier or fuzzier than before would mean the `muted` copy is not switching off. Say so and it is a small fix.
6. Reduce Motion: turn it on in iOS Settings, close the app and open it again, then the same taps should swap at once and the colours change at once.
7. VoiceOver, if used: each tab should still read "Home, tab, 1 of 5" and so on.
