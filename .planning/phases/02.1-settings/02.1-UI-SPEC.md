# Phase 2.1 - UI Design Contract (Settings)

> Design contract plan 02.1-02 builds from. PHASE 2.1. NOTHING IS BUILT. It inherits every token, type size, spacing step, radius and elevation tier from `01-foundation-accounts/01-UI-SPEC.md` (revision 18 or later) and the text roles, bar and Profile-tab rules of `02-daily-roll/02-UI-SPEC.md` (revision 6). No new colour, font, size or radius is added (section 2). The developer drew no Settings picture, so the look follows their Profile picture (screen 12) and their Notifications picture (screen 11): a serif title under a back arrow, plain rows between hairlines, nothing round, no cards. There is no imagery in this phase except the gear and the row chevrons (Ionicons).

## 2. Tokens added (the only new design values)

None. Page titles use Phase 2's `title` role (`Domine_400Regular` 32/38). Everything else is an existing token:

| Need | Token |
|---|---|
| Page, rows | `dominant` fill, `ink` Body text |
| Values on a row, helper lines, small-caps labels | `muted` (5.82:1) |
| Hairlines | `divider` |
| Pressed row | `secondary` fill |
| Log out text, error lines | `destructive` |
| Radius on every tappable | `md` (8dp) or less; nothing round is drawn by this phase |

The switch is React Native's own `Switch` (a system control, so no new native module): track `ink` when on, `divider` when off, thumb `dominant`. It is the one control whose shape the system draws; it is not styled with a radius token and the radius scans do not see it.

## 3. The gear

`SettingsGear` takes no props. Ionicons `settings-outline`, 24dp, `ink`, inside a 44dp by 44dp `Pressable` (`accessibilityRole="button"`, label 'Settings', hint 'Opens your settings.'). It pushes `/(app)/profile/settings`.

- **Current Profile page** (Phase 1's form in edit mode, which is the Profile tab after Phase 2): at the right end of the header row, `sm` after the 'RNDMRoll' label and its rule. Only in edit mode inside the tab (`edit && inTab`); never on the first-run page and never on sign-up.
- **Phase 4's Profile page:** it has no header row, so a 44dp row is added above its photo row with the gear right aligned.

## 4. The Settings page

Pushed over the Profile page with the bar showing. `Screen` with `scroll` on and `edges` top, left and right (the bar adds the bottom inset), side margins `lg`. Top to bottom:

1. **Back row**, 44dp: Ionicons `chevron-back` 22dp and 'Back' (Body), exactly the control `ProfileForm.tsx` draws, going `router.back()`.
2. **Title**, `md` below: 'Settings', `title` role, `ink`, one line.
3. **Notice line**, `sm` below: a Label in `muted`, one line, polite live region. Its 20dp is always reserved so nothing jumps. It shows 'Username changed.', 'Password changed. Other phones are signed out.' or 'Saved.' for 3 seconds after a page returns here (wiring in section 12), and is empty otherwise.
4. **Bio**, `lg` below: `BioInline` with its label on (section 7): the small-caps Label 'Bio' (capitals by style, letter spacing 1.5, `muted`), and under it, `sm`, the bio.
5. **Rows**, `lg` below. A 1dp `divider` hairline above the first row and one under each row. Each row is at least 56dp high, full width, Body role, `ink`, with a trailing area: a value in Body `muted` (one line, cut with an ellipsis) and Ionicons `chevron-forward` 20dp `muted`, `xs` apart. Pressed: `secondary` fill, no radius. In this order:
   - **Edit profile** opens `/(app)/profile/edit` (Phase 1's form: photo, name, username, bio, Log out). No value.
   - **Username** opens `/(app)/profile/username`. Value: '@' and the current username.
   - **Password** opens `/(app)/profile/password`. No value.
   - **Private account**: the switch row (section 8). No chevron.
   - **Log out**: 'Log out' in `destructive`, no chevron, opens the Log out sheet (`LogOutSheet`).
6. `xl` of space at the end.

**Log out sheet.** Phase 2's `ConfirmSheet` (the same modal, scrim, top corners and padding as Phase 1's Log out sheet, already on the `radius.lg` list): the title 'Log out of RNDMRoll?' (Heading role), the Body "You'll need to sign back in.", then two full-width rows of at least 56dp with a hairline between: 'Log out' (in `destructive` when the built `ConfirmSheet` has the per-row destructive flag, which Phase 3 adds; otherwise plain `ink`) and 'Stay logged in'. 'Log out' calls the session's `signOut()`; the root guard then returns to Welcome. The words are Phase 1's; the rows are the Phase 2 sheet's, a little different from Phase 1's two centred text buttons, so no new `radius.lg` file is needed. Phase 1's own Log out on the form page is not touched.

**Edit profile versus the other rows.** Edit profile is the existing form page for name and photo (and it still has username and bio boxes, as Phase 1 built it). The Username row is the quick way to change only the username; the Bio block above is the quick way to change only the bio.

**Posts.** There is no row for posts. A person edits or deletes a post from its entry page (Phase 3: the Edit and Delete footer), which the Phase 4 Diary and Profile page open. This is said here once so the developer can object.

## 5. The Username page

Pushed from the Username row, bar showing. `Screen` as in section 4. Top to bottom:
1. Back row (as 4.1).
2. `md` below: title 'Username' (`title` role).
3. `lg` below: `TextField` variant `soft`, label 'Username', prefix '@', the current username as the starting value, `autoCapitalize="none"`, `autoCorrect={false}`, `status` from the live check. The value is lower-cased as typed.
4. If the name is taken: `xs` below, the alternates as small chips exactly as Phase 1's form draws them (`elevation.subtle`, `radius.sm`, Label); a tap puts the alternate in the box.
5. `md` below: the Label 'This is how people find you and how you log in.' in `muted`.
6. If a save failed, `md` below: one Body line in `destructive` (section 9).
7. `lg` below: `PrimaryButton` 'Save username' (no arrow): grey (the existing disabled look) until the box holds a value that is different from the stored one, matches `^[a-z0-9_]{3,20}$` and the live check says it is free. While saving it shows its spinner.

**Live check.** Phase 1's rules, unchanged: nothing is checked while the box holds the stored username or is empty (the person's own name is never "taken" against itself); a value that is not 3 to 20 of a to z, 0 to 9 and underscore shows '3 to 20 letters, numbers, or underscores.' at once; otherwise a 400ms debounce, then `GET /usernames/available`; free shows the green 'Looks good.' (the `success` note); taken shows "That username's taken. Try one of these:" with the alternates (or "That username's taken." with none); a failed check shows "Couldn't check that username. Try again."

**Save.** `PATCH /me {username}`. Success: refresh the session user, leave the notice 'Username changed.' for Settings, go back. A 409 `username_taken` (a race) shows the taken message and its `suggestions`.

## 6. The Password page

Pushed from the Password row, bar showing. Top to bottom:
1. Back row.
2. `md` below: title 'Password'.
3. `lg` below: `TextField` soft, label 'Current password', `secureTextEntry` (off while Show is on), `autoComplete="current-password"`, `textContentType="password"`, with the Show or Hide link on the label row (Phase 1's pattern: an absolutely placed Label link, label 'Show password' or 'Hide password').
4. `md` below: `TextField` soft, label 'New password', `autoComplete="new-password"`, `textContentType="newPassword"`, its own Show or Hide link. Under it, until it is judged: the Label 'At least 8 characters.' in `muted`. On blur: too short shows 'Password must be at least 8 characters.'; over 72 bytes shows 'That password is too long. Use 72 characters or fewer.'; the same text as the current box shows 'Choose a password that is different from your current one.'; a good one shows the green 'Looks good.'. One new-password box only, like sign-up (there is no "type it again").
5. If a save failed, `md` below: one Body line in `destructive` (section 9).
6. `lg` below: `PrimaryButton` 'Save password' (no arrow): grey until the current box is not empty and the new one is good and different. Spinner while saving.

Nothing is saved on the phone except the new tokens the server returns.

**Save.** `POST /me/password {current_password, new_password}`. Success (200, a log-in shaped body): `signIn(result)` of the session context stores the new tokens and user (this phone stays signed in), the boxes are cleared, the notice 'Password changed. Other phones are signed out.' is left for Settings, go back. Failure: a `validation_failed` with `field: "current_password"` shows 'That is not your current password.' under the Current box and keeps the typed new password; any other `validation_failed` shows 'That password can't be used. Try a different one.' under the New box; 429 shows 'Too many tries. Wait a minute and try again.'; no connection shows 'Couldn't connect. Check your connection and try again.'; anything else 'Something went wrong. Please try again.'. A failed save never clears the boxes.

## 7. Bio in place (`BioInline`)

One optional prop, `label` (default off): when on, the component draws its own small-caps 'Bio' label row (Settings passes it on and draws no label itself; Phase 4's Profile page leaves it off and mounts the component under the @username). It reads `user.bio` from the session.

| State | What shows |
|---|---|
| Reading, has a bio | the bio in Body role, `ink`, left aligned, line breaks kept; under it, `xs`, the text link 'Edit bio' (Label, `ink`, underlined, 44dp hit area). The bio text is also a tap target. |
| Reading, no bio | the text link 'Add a bio' (Label, `muted`, underlined, 44dp hit area). |
| Editing | `TextField` soft, label 'Bio', hint 'Optional', multiline, 3 lines, `maxLength` 160, the count inside the box, placeholder "Tell people what you're spinning for.", focused on open. Under it, `sm` below, one row: 'Save' (`TextButton`, disabled until the text differs from the stored bio) and 'Cancel' (`TextButton`, tone `muted`), `lg` apart. A failed save shows one Label in `destructive` under the row. |
| Saving | the box is not editable and 'Save' is disabled; no spinner, no layout change. |

**Save.** `PATCH /me {bio}` with the trimmed text (an empty text clears the bio). Success: refresh the session user and go back to Reading with the new text; there is no notice. 'Cancel' drops the edit. Leaving the page while editing drops the edit (it is short and visible). The 160 limit and the control-character rule are the server's (Phase 1); the box stops typing at 160.

The current Profile page's own Bio box (in Phase 1's form, saved by 'Save changes') is left as it is.

## 8. The Private account row

A row of section 4, `Screen`-wide, at least 56dp: the label 'Private account' (Body, `ink`) at the left and the `Switch` at the right. Under the row, `xs` below inside the same hairline block, the Label in `muted`: 'Public accounts can appear on Global. Private accounts are seen by friends only.' The switch is ON when `user.account_visibility` is 'private' and OFF when it is 'public' (the default for everyone).

**Behaviour.** The whole row is one switch element: a tap anywhere on it toggles (the system switch inside it ignores touches itself). The change shows at once, the row is disabled while the save runs (`PATCH /me {account_visibility}`), and on success the session user is refreshed. On failure the switch goes back to what it was and one Label in `destructive` shows under the sentence ('Couldn't connect. Check your connection and try again.' for no connection, otherwise 'Something went wrong. Please try again.'); it clears on the next try. There is NO confirmation dialog: the choice is reversible.

**What it does.** In this phase it is only stored and shown (CONTEXT D-12). Nothing on screen changes when it is flipped, other than the switch.

## 11. Accessibility

- **Gear.** A button, label 'Settings', hint 'Opens your settings.', 44dp hit area.
- **Settings page.** The title is a header element. Each row is one button: 'Username, {name}' for the Username row, otherwise its label; hint 'Opens the page.' for the three page rows. 'Log out' is a button with the hint 'Asks first.' The back control is a button labelled 'Back'.
- **Notice line.** A polite live region, so VoiceOver reads it once when it appears.
- **Private account.** One element with `accessibilityRole="switch"`, label 'Private account', state checked or not, hint 'Public accounts can appear on Global. Private accounts are seen by friends only.' A failure message is a polite live region.
- **Username and Password pages.** Fields are labelled by their small-caps labels; the count and the 'Looks good.' note are read as Phase 1 reads them; the Show and Hide links are buttons 'Show password' and 'Hide password' for their own field (`accessibilityLabel` includes 'current' or 'new').
- **Bio.** Reading is a button: 'Bio: {text}. Edit your bio.' (no bio: 'Add a bio'). Editing: the field is labelled 'Bio', its count is read ('12 of 160 characters'); 'Save' and 'Cancel' are buttons.
- **Targets.** Every tappable is at least 44dp (rows 56, gear 44, links 44).
- **Text size.** Everything scales with the phone's text size.
- **Contrast.** `muted` on `dominant` 5.82:1, `ink` 17.32:1, `destructive` as in Phase 1, the green 'Looks good.' as in Phase 1.

## 12. Notes for the plan

- **Plan split.** 02.1-01 is the server (the visibility column and field, the change-password route, tests, cutover). 02.1-02 is the app (API calls, pure rules, the components of sections 3 to 8, three routes, the gear, a short walkthrough).
- **Wiring.** The pages read the session user (`useSession().user`) and refresh it with `reloadUser()` after a save. The new tokens of a password change go through `signIn(result)`; `lib/session/store.ts` is not edited. A tiny in-memory store (`lib/settings/notice.ts`) carries the notice from a page back to Settings: set just before `router.back()`, read by Settings on focus, cleared after 3 seconds.
- **Pure logic in pure files** (`lib/settings/rules.ts`: the username pattern, the password problems, the bio length, 'is it the same as before'), checked by a throwaway node script and by device steps.
- **Launch.** No launch file is edited. Three `Stack.Screen` lines go in `app/(app)/profile/_layout.tsx`; one cold launch is recorded after the routes exist.
- **One edit to a Phase 1 file:** `components/profile/ProfileForm.tsx` gets the gear in its header row. Phase 4 adds an optional `pushed` prop to the same file; the edits do not overlap.
- **Never run `expo lint`.** No new native module (the switch is React Native's). Tokens only, no hex. No `radius.full` or `radius.lg` is added, so Phase 2's radius lists are unchanged.

**Choices made here that you may want to change:**
- Settings is a page you reach from a gear at the top right of the Profile page, not a new tab.
- The rows are Edit profile, Username, Password, Private account and Log out, in that order. There is no row for posts: you change or delete a post from its own page (Edit and Delete), as already planned.
- Changing the username needs no password. The old name is free for others at once.
- Changing the password signs your other phones out and keeps this one signed in. A signed-in phone can keep working for up to 15 minutes before it notices.
- There is one new-password box, with no "type it again" box.
- The bio is shown as text on Settings and, later, on the Profile page, and is edited in place with Save and Cancel. The Profile page you have today already has a Bio box in its form; I left that alone.
- The account is PUBLIC unless the person switches it to private. Accounts of people under 18 START private (a recommendation you can drop by editing one line); they can switch it like anyone else.
- Flipping the switch asks nothing and saves at once. In this phase it only stores the choice; who sees which post is Phase 5 and 6's job.
- Forgot password, changing the email and deleting the account are not here (the launch list).
