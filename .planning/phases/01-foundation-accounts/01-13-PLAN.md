  <action>
`internal/middleware/recovery.go` exports `Recovery(logger *slog.Logger) gin.HandlerFunc`. It recovers a panic, logs the value and stack at error level server-side, and responds 500 with the fixed body `{"error":"server_error"}`. The stack never reaches the client: returning it would hand an attacker a map of the internals, and `RespondError` already establishes `server_error` as the opaque code for anything unmapped.

`internal/middleware/logging.go` exports `RequestLogger(logger *slog.Logger) gin.HandlerFunc` writing one structured line per request with method, path, status, duration, and client IP. It logs no headers and no request body. Add an explicit redaction helper and use it for any field that might later be logged, so the rule is enforced by a function rather than by remembering. A token or password in a log file is a durable credential disclosure that outlives the request, which is why this is stated as a hard constraint rather than a style note.

`internal/httpapi/server.go` exports `type Server struct` and `NewServer(deps Deps) *Server` where `Deps` carries the five handler values, the user repository, the JWT secret, and a logger. `(*Server) Engine() *gin.Engine` builds the engine:

Start from `gin.New()` rather than `gin.Default()`, attaching `Recovery` and `RequestLogger` explicitly so the middleware stack is visible in one place. Register `GET /healthz` returning 200 with no database call, so a liveness probe stays green during a database blip rather than cascading a restart.

Create the `/v1` group. Mount `AuthHandler` and `VerifyEmailHandler` and `OAuthHandler` on it directly, since signup, login, refresh, logout, verification, and social sign-in must all be reachable without a session. Create a nested authenticated group applying `RequireAuth(secret)` then `RequireVerified(repo)`, and mount `ProfileHandler` and `UsernameHandler` there. Applying `RequireVerified` at the group rather than per route is what makes D-04 hold for every current and future authenticated route by default; a new route added later is gated unless someone deliberately mounts it elsewhere.

Write the middleware tests covering the five behaviors. The log-redaction test asserts that a request carrying an Authorization header and a password field produces a log line containing neither value.

Wrap the engine in an explicit `&http.Server{}` with `ReadHeaderTimeout` of 10 seconds, `ReadTimeout` of 30 seconds, and `WriteTimeout` of 30 seconds. A Gin engine served without timeouts holds a connection open indefinitely on a slow client, which is a standing denial-of-service exposure rather than a tuning preference.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network -> process | Untrusted connections reach the server directly |
| process -> logs and stderr | Request data can become durable on disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SRV-01 | Information Disclosure | stack trace or panic text returned to a caller | high | mitigate | `Recovery` responds with a fixed `server_error` body and logs the stack server-side only, asserted by test |
| T-01-SRV-02 | Information Disclosure | credentials written to request logs | high | mitigate | `RequestLogger` logs no headers and no body, with an explicit redaction helper and a test asserting neither an Authorization value nor a password value appears in a log line |
| T-01-SRV-03 | Elevation of Privilege | a future authenticated route added without the verified gate | high | mitigate | `RequireAuth` and `RequireVerified` are applied to the authenticated group rather than per route, so a new route inherits both by default |
| T-01-SRV-04 | Denial of Service | slow-client connection exhaustion | high | mitigate | Explicit `ReadHeaderTimeout`, `ReadTimeout`, and `WriteTimeout` on the http.Server rather than serving a bare Gin engine |
| T-01-SRV-05 | Denial of Service | process starting with partial or invalid configuration | medium | mitigate | `MustLoad` fails fast and `NewPool` pings at construction, so misconfiguration stops the process at launch |
| T-01-SRV-06 | Tampering | in-flight write severed by a deploy | medium | mitigate | SIGINT and SIGTERM trigger a bounded 15 second graceful shutdown before the pool closes |
| T-01-SRV-07 | Information Disclosure | health endpoint revealing internal state | low | mitigate | `GET /healthz` returns a bare 200 with no version, dependency status, or database detail |
| T-01-SRV-08 | Tampering | plaintext HTTP in a deployed environment | high | transfer | TLS termination is an infrastructure concern rather than application code, as RESEARCH.md's Security Domain V6 row notes; recorded for the deployment phase and re-checked at the plan 01-15 walkthrough |
</threat_model>
