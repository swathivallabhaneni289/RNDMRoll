## Lessons from 2026-10-09 (read these)

- A terse screenshot complaint ("its all empty", "like this", "the password is not added after the username") was guessed wrong three times. One concrete example with real values settled the design. Ask one plain question with an example before building.
- A hot update can silently not reach the phone. Take a screenshot after every app edit; restart the app at a boundary if nothing changed, and say so.
- The developer hates typing in tests. Use accounts made through the API and keep checks short. Make throwaway accounts through the API and delete them yourself.
- Dropping a column is the opposite of adding one: restart the API on the new code FIRST (it works against the old schema), then migrate `rndmroll_dev`, then `rndmroll_test`. The API does not migrate itself (`~/go/bin/migrate`). The start script `~/.local/share/rndmroll-work/start-api-test-mode.sh` rebuilds and restarts it.
- A grep for "google" also hits `github.com/google/uuid` and the font packages `@expo-google-fonts/*`; those stay.
- Another iOS system prompt ("Save Password?") can appear when a form with password boxes reloads: tap Not Now.
- Helper agents work well for paper (documents) and for pure removals with a precise list; check their diffs and the gates yourself.
