Create `components/brand/BrandMark.tsx` exporting `BrandMark({ size = 64, color = tokenColor.ink }: { size?: number; color?: string })`. It renders a single `react-native-svg` `<Svg viewBox="0 0 40 40" width={size} height={size}>` containing exactly five `<Circle>` elements at `r={4}` (8dp diameter) in the die-face-five quincunx: centers at (8,8), (32,8), (20,20), (8,32), (32,32). Fill is the `color` prop, opacity 1, transparent background, no `<Rect>`, no border, no badge container. UI-SPEC's Focal Points section requires the mark to carry no elevation and no fill container so it cannot outweigh the CTA group on the choose-method screen.

Create `components/brand/BackgroundDotGrid.tsx` exporting `BackgroundDotGrid()`. It renders an absolutely-positioned, `pointerEvents="none"` `<Svg>` filling its parent, defining a `<Defs><Pattern id="dotGrid" width={texture.spacing} height={texture.spacing} patternUnits="userSpaceOnUse"><Circle cx r fill={texture.dotColor} /></Pattern></Defs>` and a `<Rect width="100%" height="100%" fill="url(#dotGrid)" />`. Dot radius is `texture.dotDiameter / 2`, grid pitch is `texture.spacing` on both axes, and the dot fill comes from `texture.dotColor`. The layer is static: no animation, no parallax, no transform, matching PROJECT.md's standing "no over-the-top scroll animations" constraint and UI-SPEC's explicit static requirement.

Neither component takes an elevation, shadow, or accessibility role: both are decorative. Mark the dot grid `accessibilityElementsHidden` and `importantForAccessibility="no-hide-descendants"` so screen readers skip it.

`components/ui/AppText.tsx` exports `AppText({ role = 'body', tone = 'default', children, ...rest })` where `role` is one of `'body' | 'label' | 'button' | 'heading' | 'display'` and `tone` is one of `'default' | 'muted' | 'destructive' | 'success' | 'onInk'`. It spreads the matching entry from the `type` token (fontSize, lineHeight, fontFamily) and maps tone to `color.ink`, `color.muted`, `color.destructive`, `color.success`, and `color.dominant` respectively. It never sets a numeric `fontWeight`. Also export `TextLink({ onPress, children })`, which renders button-role type with `textDecorationLine: 'underline'` and `color.ink`, the treatment UI-SPEC reserves for "Log in instead" and "Sign up instead".

`components/ui/Screen.tsx` exports `Screen({ children, texture = false, scroll = true })`. It renders a `SafeAreaView` with `backgroundColor: color.dominant`, horizontal padding `space.lg` (24), and, when `texture` is true, the `BackgroundDotGrid` behind the content at the lowest z-index. UI-SPEC scopes the texture to the choose-method screen only, so the prop defaults to false and every other screen simply omits it. When `scroll` is true the children sit inside a `KeyboardAvoidingView` plus `ScrollView` with `keyboardShouldPersistTaps="handled"` so form screens stay usable with the keyboard up.

`components/ui/StepDots.tsx` exports `StepDots({ total, current })`. It renders `total` circles of 8dp diameter spaced `space.sm` apart; the dot at index `current` uses `color.ink`, all others use `color.inkInactive`. It carries `accessibilityRole="progressbar"` with an `accessibilityValue` of `{ min: 1, max: total, now: current + 1 }`. D-05 defines a six-step onboarding sequence; screens pass `total={4}` covering the four steps the user actually works through after choosing a method: verify email, name, username, photo. Step 1 is the method chooser, which precedes the indicator, and step 6 is landing in the app, which is an outcome rather than a step with its own dot.

`components/ui/IconBadge.tsx` exports `IconBadge({ name, surface, accessibilityLabel })` where `name` is an Ionicons glyph name and `surface` is `'dominant' | 'secondary'` naming the surface the badge sits ON. It renders a 40dp circle using the circular radius token, holding a 20dp Ionicons glyph in `color.ink`, with `elevation.card`'s shadow treatment and a `borderWidth: 1` (an explicit 1, never `StyleSheet.hairlineWidth`, per UI-SPEC) in `color.inkInactive`. The fill inverts against `surface`: when `surface` is `'secondary'` the badge fills with `color.dominant`, and when `surface` is `'dominant'` the badge fills with `color.secondary`. UI-SPEC states this rule explicitly: a badge is always filled with the other neutral relative to its background, never the same surface color and never a low-opacity Ink tint. The `accessibilityLabel` prop is required, not optional, because both uses of this badge are icon-only.

All four components hard-code `borderRadius: radius.md` (8). None of them accepts a radius prop. PROJECT.md bans pill-shaped buttons and UI-SPEC defines a pill as a radius at or above half the element height, capping tappable elements at 8dp with no exceptions. The 24dp token exists only for the profile-view container card and the log-out sheet, and the circular token only for avatars and icon badges. Making radius non-configurable here is what makes the ban structural rather than a review note.
<!-- planner-discipline-allow: radius.lg -->
<!-- planner-discipline-allow: radius.full -->

`components/ui/PrimaryButton.tsx` exports `PrimaryButton({ label, onPress, disabled, loading })`. Enabled state: `elevation.raised` (Ink `color.ink` fill, `shadowColor` Ink, offset 0/4, opacity 0.18, radius 10, Android elevation 6), label rendered through `AppText` with `role="button"` and `tone="onInk"`. Disabled or loading: fill becomes `color.inkDisabled`, label color becomes `color.onInkDisabled`, and the component switches to `elevation.subtle`, because UI-SPEC states a shadowed button under an inert control reads as a bug. Minimum height is `minTouchTarget` (44). When `loading` is true it renders an `ActivityIndicator` in `color.dominant` in place of the label and sets `accessibilityState={{ busy: true }}`. `disabled` also sets `accessibilityState={{ disabled: true }}`.

`components/ui/TextButton.tsx` exports `TextButton({ label, onPress, disabled, tone = 'default' })`. Plain text, no fill, no border, no shadow, no elevation token at all, `minTouchTarget` hit area via `hitSlop`. This is the "Skip for now" and "Resend email" treatment. When `disabled` is true the label renders with `tone="muted"`.

`components/ui/MethodButton.tsx` exports `MethodButton({ provider, label, onPress, loading, disabled })` where `provider` is `'email' | 'apple' | 'google'`. Full-width, `backgroundColor: color.secondary`, `borderRadius: radius.md`, `borderWidth: 1` in `color.inkRest`, minimum height `minTouchTarget`, containing a 20dp Ionicons glyph (`mail-outline`, `logo-apple`, `logo-google`) in `color.ink` at `space.sm` from a centered `AppText` `role="button"` label. When `loading` is true the glyph and label are replaced by an `ActivityIndicator` in `color.ink`. Per UI-SPEC's social sign-in contract, tapping one button must disable all three, so the screen owns that state and passes `disabled` to the other two; this component only renders what it is told.

`components/ui/TextField.tsx` exports `TextField({ label, value, onChangeText, error, status, ...TextInputProps })`. Layout: an `AppText role="label"` above a `TextInput` with `backgroundColor: color.secondary`, `borderRadius: radius.md`, `borderWidth: 1`, `borderColor: color.inkRest`, and `minHeight: minTouchTarget`. On focus the border steps to `borderColor: color.ink` and `borderWidth: 1.5`, which is UI-SPEC's declared two-axis (color plus width) active-state step. When `error` is a non-empty string, render it directly below the field, left-aligned, through `AppText role="label" tone="destructive"`, and set `accessibilityInvalid`. The optional `status` prop is `'idle' | 'checking' | 'available' | 'taken'` and drives an inline trailing adornment used only by the username step: `checking` renders a small `ActivityIndicator` plus the text `Checking...`; `available` renders an Ionicons `checkmark-circle` glyph in `color.success` plus the label `Available`; `taken` renders nothing here because the taken state uses the error slot. The status adornment carries an `accessibilityLabel` because it is icon-bearing.
