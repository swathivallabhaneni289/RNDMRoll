This screen does NOT use the shared `Screen` component. `Screen` applies a Dominant background, a SafeAreaView, and `space.lg` horizontal padding, all three of which fight a full-bleed cover. Render a plain `View` with `flex: 1` instead, and read `useSafeAreaInsets()` and `useWindowDimensions()` directly for placement.

Layer order, bottom to top: `<PhotoPlaceholder variant="cover" />` absolutely filling the screen; then `<PhotoScrim topOpaqueFraction={...} />`; then the content. Do not render `BackgroundDotGrid`: UI-SPEC scopes the dot grid to choose-method only and states directly that layering it over full-bleed photography would read as noise.

Compute the scrim's top zone rather than hardcoding a number. Set `topOpaqueFraction` to `Math.max(SCRIM_TOP_SAFE_FRACTION, (insets.top + TAGLINE_BLOCK_HEIGHT + space.sm) / height)`, where `TAGLINE_BLOCK_HEIGHT` is a module constant equal to twice the Label role's `lineHeight` from the tokens module, since the tagline is two lines of Label type. UI-SPEC requires the tagline to sit inside the flat, fully opaque zone, and on a notched device the declared 8 percent is smaller than the status-bar inset plus two lines of text, so a fixed fraction would push the tagline's second line into the fade band where no contrast is guaranteed. Raising the flat zone preserves the guarantee UI-SPEC states as the point of the scrim; the fade band keeps its declared depth automatically because `PhotoScrim` derives its end from this value.

**Tagline.** Top-left, positioned at `top: insets.top` with `left: space.lg`, rendered through `AppText role="label" tone="onInk"` so it resolves to Dominant on the Ink scrim. The string is exactly two lines: `one roll.` then `one real moment.`, taken verbatim from the Copywriting Contract, rendered as one text node containing a newline rather than two stacked elements, so the two-line block height the scrim computation assumes is the height that actually renders.

**Wordmark.** Anchored in the bottom flat zone, `AppText role="display" tone="onInk"` reading `RNDMRoll`. Note the exact casing: the Copywriting Contract locks the same string the choose-method screen uses, deliberately rather than the source brief's lowercase styling, so the app carries one brand string rather than two differently-cased variants. Render the wordmark text alone. Do NOT render the five-pip brand glyph here: UI-SPEC keeps the full mark-plus-wordmark lockup exclusive to choose-method, and this screen carries a typographic-only variant of the name.

**CTA.** Directly below the wordmark, `<PrimaryButton label="Get started" variant="onPhoto" ... />`. The on-photo variant is what inverts the fill to Dominant and the label to Ink, and UI-SPEC adds that variant for this button and this button only, because the standard Ink fill would merge into the dark scrim behind it instead of separating from it.

Position the wordmark and CTA as one bottom-anchored group whose bottom edge clears `insets.bottom` and whose top edge stays below `height * (1 - SCRIM_BOTTOM_SAFE_FRACTION)`, so both sit inside the bottom flat zone. Use the exported constant rather than retyping 0.28.

**Behavior.** The CTA navigates to `/(auth)/ritual`, the next screen in the sequence. It does NOT write the intro-seen flag: the user has not finished the sequence yet, and a cold start from the middle of it should return to the cover rather than skip the rest.

The Interaction Contracts sentence is best read as making the narrower point it also makes, that both CTAs are straight navigations rather than state-machine transitions, which stays true under this reading. Record this resolution in the plan SUMMARY so the plan 01-15 checkpoint can confirm it.

This screen has no step indicator. UI-SPEC places Welcome outside the numbered run as a cover screen, matching the source brief's own progress indicator first appearing on the second screen.

Set the status bar to light content for this screen only, through `expo-status-bar`'s `<StatusBar style="light" />`, since this is the one screen in the phase whose top edge is dark. The app-wide light appearance lock in `app.json` is unaffected.
