Implement all five states of UI-SPEC's username state machine through the `TextField` `status` and `error` props:

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device camera and library -> storage | A user file leaves the device for object storage |
| user input -> profile record | Name and username become durable identity |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-ONB-07 | Spoofing | username claimed between the availability check and the save | medium | mitigate | The insert-time 409 is a designed state in the UI rather than an error path: the screen re-renders the taken state with fresh alternates, so the race resolves without the user losing their place |
| T-01-ONB-08 | Denial of Service | availability endpoint called on every keystroke | medium | mitigate | 400 millisecond debounce on the client, matched by the 20 per minute per-subject server limit from plan 01-11 |
| T-01-ONB-09 | Information Disclosure | photo library access requested more broadly than needed | medium | mitigate | Permissions requested on demand at tap time rather than at screen mount, and a denial leaves the step fully usable through the skip path |
| T-01-ONB-10 | Tampering | oversized or non-image upload | medium | mitigate | Content type and size are sent to `POST /me/avatar/upload-url` and bound into the presigned request by plan 01-11, so the storage provider rejects a mismatched upload regardless of client behavior |
| T-01-ONB-11 | Information Disclosure | Apple-supplied name treated as verified identity | low | accept | The prefilled name is untrusted display text, editable by the user before saving, and is never used for authentication or lookup |
</threat_model>
